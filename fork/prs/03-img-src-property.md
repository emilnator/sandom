# DOM: HTMLImageElement and HTMLSourceElement, with reflected src, srcset, sizes, alt, width and height

Branch: `fix/03-img-src-property`

## What was wrong

`<img>` and `<source>` were plain `SDHTMLElement`s, and there was no `HTMLImageElement` or `HTMLSourceElement` global. Setting an image's source as a property, `img.src = url`, created an own data property on the element instead of setting the `src` attribute, so the image never loaded and rendered blank. React and Preact set `src` this way, and so do most libraries that build images in script. `img instanceof HTMLImageElement` also threw, because the global didn't exist.

## What the spec says

HTML §4.8.3 (`HTMLImageElement`) and §4.8.2 (`HTMLSourceElement`), with §2.6.1, "Reflecting content attributes in IDL attributes":

- `src` is a `USVString` reflecting a URL. It reads the attribute parsed against the document's base URL, `""` when the attribute is absent, and the raw value when it doesn't parse.
- `srcset`, `sizes` and `alt` on `img`, and `srcset`, `sizes`, `media` and `type` on `source`, reflect as strings, reading `""` when absent.
- On `source`, `width` and `height` are reflected `unsigned long`s. They read 0 when the attribute is absent, invalid, or outside 0–2147483647, and setting a value outside that range stores 0.
- On `img`, setting `width` and `height` reflects the same way, but reading them returns the rendered size while the image is rendered, and otherwise its natural size or 0.

## What changed

- `src/dom/node.js`
  - Adds `SDHTMLImageElement` and `SDHTMLSourceElement`, next to `SDHTMLIFrameElement`, and passes them to `createElementFamily`.
  - Adds a small `reflectAttributes` helper that defines the accessors above on each prototype.
    - The accessors are non-enumerable and configurable, like the generated bindings', and setters go through `setAttribute`.
    - `src` resolves against `ownerDocument.baseURI`, so `<base href>` applies.
- `src/dom/dom-bindings.generated.js` (`createElementFamily`): maps `img` and `source` in the HTML namespace to the new classes, in both `prototypeFor` and `construct`. Parsed, cloned and `createElement`-made elements all get them.
- `src/dom/component-globals.js`: exposes `HTMLImageElement` and `HTMLSourceElement`.

**The generated file:** `dom-bindings.generated.js` says it's generated by `tools/generate-dom-interfaces.js` from `src/dom-wasm/dom-interfaces.json`. Neither file is in this repository, so this PR edits the generated output directly. **The same two cases need adding to `dom-interfaces.json`** (the `img` → `SDHTMLImageElement` and `source` → `SDHTMLSourceElement` entries of the element family), or the next regeneration will drop them. The reflected attributes could also move into the IDL, as `HTMLScriptElement.src` already is.

**Not in this PR:**

- `crossOrigin`, `decoding` and `loading` are enumerated attributes with their own missing-value and invalid-value defaults (`null`/`"anonymous"`, `"auto"`, `"eager"`). Reflecting them as plain strings would read wrong values, so they're left out. Preact falls back to `setAttribute` for them, since they aren't properties of the element.
- `img.width` and `img.height` read the content attribute, like `source`'s. A browser returns the rendered size there: an `<img>` sized only by CSS to 30×20 reads `[0, 0]` here and `[30, 20]` in Chrome. Setting them, which is what frameworks do, is exact.
- `createElementNS(HTML_NS, "IMG")` gives an `HTMLImageElement` here, though Chrome matches the local name case-sensitively there. The element family already matched `button`, `input` and the rest that way; this PR only adds two cases to it.

## How it was verified

The repo has no test suite for `src/dom` (the maintained Chrome-comparison tests aren't published), so this was checked with a standalone Deno repro. It uses `renderComponent` with `url: "https://example.test/page/"`:

| Check | Before | After |
|---|---|---|
| `img.src = dataURL` sets the attribute | `null` | the URL |
| `img.alt = "dot"` sets the attribute | `null` | `"dot"` |
| `img.width = 20` sets the attribute | `null` | `"20"` |
| `source.srcset = …` / `source.sizes = …` | `null` | the values |
| `img.src` with `src="pic.png"` | `undefined` | `"https://example.test/page/pic.png"` |
| `img.src` with no attribute | `undefined` | `""` |
| `img instanceof HTMLImageElement` | false | true |
| the image set by property loads: `[offsetWidth, offsetHeight]` for a 2×1 PNG at `width=20` | `[100, 0]` | `[20, 10]` |

- Before: 9 failed.
- After: all 9 pass.

A further check covered:

- parsed `<img>`/`<source>`, `cloneNode()` and `createElement("IMG")` are instances of the new classes;
- `width="20px"` reads 20, and `width = -1`, `"abc"` and `3e9` store `"0"`;
- `src` follows a `<base href>`;
- an SVG `<image>` isn't an `HTMLImageElement`.

Unrelated repros give the same results as before.
